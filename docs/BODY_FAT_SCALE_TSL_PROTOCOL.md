## 1. 协议帧结构解析

蓝牙体脂秤采用 **BLE 无连接广播上报机制**（支持 BLE 4.0/5.0 网关免配对实时嗅探）。

### 1.1 完整广播 vs 厂商数据域
- **BLE 原始广播包 (17 字节)**：`[Len: 0x10] [Type: 0xFF] [数据域 15 字节...]`
- **厂商数据域 (15 字节，以 0xC0 开头)**：绝大多数 MQTT 蓝牙网关（如 Cassia、ESP32 蓝牙雷达、Minew 网关）转发到 MQTT Topic 时，Payload 即为这 **15 字节**。

### 1.2 15 字节厂商数据域字节映射表
| 偏移 (Offset) | 长度 (Length) | 字段标识 | 字段名称 | 数据类型 | 缩放系数 | 单位 | 说明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **0** | 1 Byte | `header` | 包头版本号 | UINT8 | 1.0 | - | 固定 `0xC0`，用于设备型号识别过滤 |
| **1** | 1 Byte | `seq` | 流水号 | UINT8 | 1.0 | - | 1~255 循环；非锁定时每包递增，锁定后保持不变 |
| **2 ~ 3** | 2 Bytes | `weight` | **体重** | **UINT16_BE** | **0.1** | kg | **大端序**（高字节在前，低字节在后）。例如 `00 AD` = 173 -> 17.3 kg |
| **4 ~ 5** | 2 Bytes | `impedance` | **人体阻抗** | **UINT16_BE** | **0.1** | Ω | **大端序**（高字节在前，低字节在后）。例如 `13 7D` = 4989 -> 498.9 Ω |
| **6 ~ 7** | 2 Bytes | `product_id`| 产品 ID | UINT16_BE | 1.0 | - | 固定 `00 02`，体脂秤专属识别号 |
| **8** | 1 Byte | `status` | 消息体属性 | UINT8 | 1.0 | - | 包含设备类型、单位、小数位及**锁定标志**（见下节） |
| **9 ~ 14**| 6 Bytes | `mac` | MAC 地址 | HEX/BYTES | - | - | 蓝牙硬件 MAC 地址（高字节在前） |

## 2. 消息体属性位说明 (Byte 8)

Byte 8 是体脂秤的核心状态寄存器，按位 (Bit) 定义：

```
+-------+-------+-------+---------------+---------------+-------+
| Bit 7 | Bit 6 | Bit 5 | Bit 4 | Bit 3 | Bit 2 | Bit 1 | Bit 0 |
|  保留 (全 0)  | 类型  |   单位选择    |   小数位数    | 锁定  |
+-------+-------+-------+---------------+---------------+-------+
```

1. **Bit 5 (设备类型)**：
   - `0` = 体重秤
   - `1` = 体脂秤
2. **Bit 4~3 (单位选择)**：
   - `00` = KG (默认)
   - `01` = 斤
   - `10` = LB (磅)
   - `11` = ST:LB (英石:磅)
3. **Bit 2~1 (小数位数)**：
   - `00` = 1 位小数 (默认，实际值 = 原始值 * 0.1)
   - `01` = 0 位小数 (实际值 = 原始值 * 1.0)
   - `10` = 2 位小数 (实际值 = 原始值 * 0.01)
4. **Bit 0 (数据锁定标志，最关键！)**：
   - `0` = **非锁定实时动态数据**（人在秤上晃动、正在称重或测阻抗中）
   - `1` = **锁定最终稳定数据**（称量已完成，数值闪烁锁定，代表最终有效结果）
   - **TSL 告警掩码**：配置 `alarmBitmask: 1` 即可在锁定瞬间触发状态捕获或高亮高优先级展示！

## 3. 可直接复制粘贴的 TSL 物模型 JSON

在 **MQTT Assistant APP -> 设置 -> TSL 物模型管理 -> 导入/新建**，或在 **TSL Web Studio** 中直接粘贴以下内容：

```json
{
  "protocolId": "body_fat_scale_ble_v1",
  "name": "蓝牙智能体脂秤广播协议",
  "format": "HEX",
  "matchTopic": "medical/+/body_scale/#",
  "builtin": false,
  "enabled": true,
  "fields": [
    {
      "identifier": "weight",
      "name": "体重",
      "offset": 2,
      "length": 2,
      "type": "uint16_be",
      "scale": 0.1,
      "precision": 1,
      "unit": "kg",
      "warnMin": 20.0,
      "warnMax": 150.0
    },
    {
      "identifier": "impedance",
      "name": "人体生物阻抗",
      "offset": 4,
      "length": 2,
      "type": "uint16_be",
      "scale": 0.1,
      "precision": 1,
      "unit": "Ω",
      "warnMin": 200.0,
      "warnMax": 1200.0
    },
    {
      "identifier": "is_locked",
      "name": "测量锁定标志(稳定完成)",
      "offset": 8,
      "length": 1,
      "type": "uint8",
      "scale": 1.0,
      "precision": 0,
      "unit": "",
      "alarmBitmask": 1
    },
    {
      "identifier": "seq",
      "name": "报文流水号",
      "offset": 1,
      "length": 1,
      "type": "uint8",
      "scale": 1.0,
      "precision": 0,
      "unit": ""
    },
    {
      "identifier": "product_id",
      "name": "产品识别码",
      "offset": 6,
      "length": 2,
      "type": "uint16_be",
      "scale": 1.0,
      "precision": 0,
      "unit": ""
    }
  ]
}
```

> **注**：若您的网关上报带完整的 2 字节 BLE 头（即以 `10 FF C0 ...` 开头共 17 字节），只需将上述各字段的 `offset` 分别加 2（例如 weight offset 为 4）。

## 4. 官方真实广播 Hex 报文验证样例

### 报文十六进制串：
```hex
C0 CB 00 AD 13 7D 00 02 21 00 11 22 33 44 55
```

### 逐字段解析对照：
| 字节位置 | 原始 Hex | 解析计算过程 | 物理量输出 | 状态说明 |
| :--- | :--- | :--- | :--- | :--- |
| **0** | `C0` | 固定帧头 | `0xC0` | 版本标志通过 |
| **1** | `CB` | 十六进制 0xCB | 流水号 = `203` | 报文序列标识 |
| **2~3** | `00 AD` | 大端拼合 `0x00AD` = 173，乘以 0.1 | **`17.3 kg`** | 体重测量值 |
| **4~5** | `13 7D` | 大端拼合 `0x137D` = 4989，乘以 0.1 | **`498.9 Ω`** | 人体生物电阻抗 |
| **6~7** | `00 02` | 大端拼合 `0x0002` = 2 | 产品 ID = `2` | 匹配体脂秤产品 |
| **8** | `21` | 二进制 `00100001`：<br>• Bit5=1 (体脂秤)<br>• Bit4-3=00 (KG)<br>• Bit2-1=00 (1位小数)<br>• Bit0=1 (数据已锁定) | **已锁定稳定值** | 触发 `alarmBitmask=1` 告警/锁定捕获 |
| **9~14**| `00 11 22 33 44 55`| 蓝牙 MAC | `00:11:22:33:44:55` | 设备唯一硬件地址 |

## 5. MQTT 网关拦截与 SI Agent 联动建议

1. **实时雷达过滤锁定值**：
   - 称重过程中秤会连续发送几秒动态变化的报文（`Bit0 = 0`），直到人体站稳且测脂完成才会置 `Bit0 = 1`。
   - 可以在 SI Agent 中下达指令：*“拦截体脂秤稳定的最终测量记录”*，SI Agent 将自动检查 `is_locked` 字段（或位掩码 0x01），仅归档稳定的终值，避免中间波动数据刷屏。
2. **体脂率与 BMI 计算**：
   - 该秤在广播中直接输出的是最底层、最精准的物理量：**净体重 (kg)** 与 **生物阻抗 (Ω)**。
   - 结合身高、年龄、性别输入，即可在端侧通过标准的 BIA 阻抗体脂算法直接推算出体脂率、肌肉量、骨量与基础代谢率！
